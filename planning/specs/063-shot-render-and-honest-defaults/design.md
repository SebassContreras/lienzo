# 063 — shot-render-and-honest-defaults — Design

## Approach

- D1@1 (implements R2, R3): The camera moves out of `drawElements`, which a group calls again for its children (that is why the camera was applied once per level). It is applied per element in `drawScene`, to top-level elements only, and only when the element has `shot`. The camera is read from the element's own shot (`resolveShotCamera(shotOf(el), t)`) instead of "the active shot", so two shots overlapping in a transition each keep their own camera. Trade-off: one `save`/`restore` per shot-bound element instead of one per frame — negligible next to drawing; if a profile ever shows otherwise, consecutive elements of the same shot can share one transform. _(standard: a camera views each layer once and only layers that opt in — After Effects cameras, https://helpx.adobe.com/after-effects/using/cameras-lights-points-interest.html)_
- D2@1 (implements R1): A pure `shotTransitionAt(shot, t, scene) → { alpha, dx, dy, scale }` in `src/engine/shots.ts` turns the transition window that `isElementActiveInShot` already opens into entering and exiting progress: `fade` drives alpha, `slide` offsets by ±scene width, `zoom` scales 0.8→1 around the center. `drawScene` composes it with D1's camera inside the same `save`/`restore`. Trade-off: one fixed presentation per kind, no `direction` — the same three Remotion ships by default; `slide.direction` can be added to `ShotTransitionSchema` when someone asks. _(standard: Remotion `TransitionSeries` presentations — https://www.remotion.dev/docs/transitions/transitionseries, https://www.remotion.dev/docs/transitions/presentations/fade)_
- D3@1 (implements R4): Reproduce first: a test compares `textLayout(el).w` with the drawn width for `at` text with no `w` (reported: 844 px measured, ~920 px drawn). The likely causes are a font outside the six bundled ones falling back to estimated measurement, a measurement taken before the `FontFace` has loaded, or `letterSpacing` counted on only one side. The fix stays inside `src/engine/text-measure.ts`, so layout and drawing share one measurer. Trade-off: the cause is unconfirmed — no code changes on a guess, and this item is revised through `spectrace-change` if the test points elsewhere.
- D4@1 (implements R5): The defaults change where they are declared: `fill.opacity: 1` in `src/traits/fill.ts` and the path descriptor, `border.width: 0` on path, and `path` handled by `applySceneDefaults` (`src/service/compact/defaults.ts`). Because the draw-on animation (`progress`) needs a visible stroke, applying it (compact expansion or the editor's "Trazo dibujado") sets `border.width: 3` when the element has no width of its own. Trade-off: existing scenes that relied on the old defaults change look, omega-v2's `path()` among them. Mitigation: a render audit of every tracked scene and preset before and after, pinning the old values explicitly wherever the look must stay, plus a `changes.md` entry.
- D5@1 (implements R6): A pure `ignoredPaths(input, parsed): string[]` in `src/model/ignored.ts` walks the raw input and the Zod-parsed output side by side and lists the keys present in the input but missing from the output. It works on plain data, so it depends on no Zod internals and survives Zod upgrades. `scene_validate`, `scene_build` and `expandCompact` add these paths to their existing `notices`. Trade-off: one extra linear walk per validation, small next to parsing. `z.strictObject` was rejected because it turns unknown keys into errors and would break older scenes. _(standard: Zod objects strip unknown keys by default; strict objects reject them — https://zod.dev/api#objects)_
- D6@1 (implements R7): Pure `renameAssetRefs(scene, from, to)` and `assetUsers(scenes, src)` in `src/model/asset-refs.ts` walk elements, groups and symbols for asset `src` values (image, audio, 3D, `audioTracks`). `asset_rename` and `asset_delete`, one file each in `src/service/tools/` (A20), move or remove the file through `src/service/asset-helpers.ts` and rewrite scenes with `writeJson`; the assets tab calls the same functions through the existing API. Trade-off: a rename rewrites several scene files without a transaction, so a crash midway could split references. Mitigation: scenes are rewritten first and the file moves last, and rerunning the same rename is idempotent.
- D7@1 (implements R8): The notice composition the tool uses (`prepareScene` + `fontNotices` + `ignoredPaths`) is extracted into `src/service/scene-notices.ts`, which now has two callers, the tool and the editor. The editor's "Revisión" section lists it under "Avisos". A notice carries an optional element `id`, and clicking it selects that element. Trade-off: the browser cannot scan font folders, so it uses the `/api/fonts` list the editor already loads, which is the same source.
- D8@1 (implements R9): Duplicate and align recipes go in `.agents/skills/lienzo-usage/`, with no code. Trade-off: two calls instead of one; if agents keep getting them wrong, that is the signal to add a tool (YAGNI until then).
- D9@1 (implements R10): Once D1–D4 pass, the skill workarounds are reverted in `.agents/skills/lienzo-usage/` and the regression scenes are re-rendered.

## Sequencing

D1 before D2 (transitions compose with the per-element camera); D5 before D7 (the editor shows its notices); D4 together with its render audit, and both before D9. D3 starts with its reproducing test and can run in parallel.
