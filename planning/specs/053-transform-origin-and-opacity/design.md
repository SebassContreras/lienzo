# 053 — transform-origin-and-opacity — Design

## Approach

- D1@1 (implements R1, R5): Every element supports an optional `origin?: { x: number; y: number }` field in box fractions (`0` to `1`, default `{ x: 0.5, y: 0.5 }` when omitted) in `ElementOf` (`src/components/descriptor.ts`) and `ElementSchema` (`src/model/element-schema.ts`), and `AnimState` (`src/animations/kind.ts`) gains `originX: number` and `originY: number` defaulting to `0.5` in `rest()` _(standard: CSS Transforms Module Level 1 `transform-origin: 50% 50%` — https://www.w3.org/TR/css-transforms-1/#transform-origin-property)_. `animate(el, t, scene)` (`src/engine/animate.ts`) copies `el.origin?.x ?? 0.5` and `el.origin?.y ?? 0.5` onto `transform.originX` and `transform.originY` after evaluating keyframe tracks and preset animations. `withTransform(ctx, box, st, draw)` (`src/engine/paint.ts`) and `applyTransform(ctx, box, st)` (`src/engine/clip.ts`) compute the pivot point as `ox = box.x + box.w * (st.originX ?? 0.5)` and `oy = box.y + box.h * (st.originY ?? 0.5)`, translating to `(ox + st.dx, oy + st.dy)`, rotating, skewing, scaling, and translating back by `(-ox, -oy)`. When `origin` is omitted or `{ x: 0.5, y: 0.5 }`, `(ox, oy)` equals the box center and all canvas calls are identical to before 053 (R5).
- D2@1 (implements R2): In `src/model/compact.ts`, `CompactOriginSchema` accepts `AnchorNameSchema` (`"center"`, `"top"`, `"bottom"`, `"left"`, `"right"`, `"top-left"`, `"top-right"`, `"bottom-left"`, `"bottom-right"`), a 2-tuple `[x, y]`, or `{ x, y }` (each `0` to `1`) on `baseSpecialFields.origin` _(standard: CSS Transforms `transform-origin` keyword and percentage syntax — https://www.w3.org/TR/css-transforms-1/#transform-origin-property)_. Pure helper `resolveOrigin(input)` in `src/service/compact/layout.ts` maps named anchors (`"top-left": { x: 0, y: 0 }`, `"top": { x: 0.5, y: 0 }`, `"top-right": { x: 1, y: 0 }`, `"left": { x: 0, y: 0.5 }`, `"center": { x: 0.5, y: 0.5 }`, `"right": { x: 1, y: 0.5 }`, `"bottom-left": { x: 0, y: 1 }`, `"bottom": { x: 0.5, y: 1 }`, `"bottom-right": { x: 1, y: 1 }`), tuples `[x, y]`, and `{ x, y }` objects into canonical `{ x, y }` fractions in `buildElement` (`src/service/compact/expand.ts`).
- D3@1 (implements R3, R5): A shared `elementOpacity(section, defaultValue = 1)` field builder in `src/components/fields/box.ts` returns `num(defaultValue, { label: "Opacidad", section, max: 1, step: 0.01, bounds: [0, 1] })` with `.default(defaultValue)` on its Zod schema so scenes and presets saved before 053 without `opacity` parse as their default (`1`) and existing default elements keep their exact field shapes in `presets/diff.ts` unless modified _(judgement, no standard)_. Every component descriptor that lacked top-level `opacity` (`rect`, `ellipse`, `polygon`, `star`, `arrow` via `shapeFields` in `Forma`; `group` in `Grupo`; `particles` in `Partículas`; `three` in `Forma`; `badge` in `Insignia`; `progress` in `Progreso`; `counter` in `Número`; `bubble` in `Estilo`; `steps`, `table`, `chart` in `Color`; `list` in `Texto`; `code` in `Estilo`; `path` in `Forma`; `subtitles` in `Subtítulos`) includes `opacity`, exposing it automatically in `ElementSchema`, `CompactElementSchema`, `d.animatable` (keyframe tracks and `keyframe_set`), and the inspector (`src/editor/field-editor.tsx`).
- D4@1 (implements R4, R5): `animate(el, t, scene)` (`src/engine/animate.ts`) folds the element's own `opacity` (`now.el.opacity ?? 1`) into `transform.alpha` ONLY for component kinds that do not already apply `el.opacity` inside their own `draw` function (or uniformly via `drawElements` / `withTransform`): specifically, in `drawElements` (`src/engine/render.ts`) and `placedElementsAt` (`src/service/layout.ts`), each element's effective opacity is `(now.el.opacity ?? 1) * now.transform.alpha` multiplied by its ancestor groups' effective opacities _(standard: W3C SVG 2 / CSS Color 4 group opacity compositing — https://www.w3.org/TR/css-color-4/#transparency)_. When `(now.el.opacity ?? 1) * now.transform.alpha <= 0`, `drawElements` returns early without invoking the component's `draw` function (so `opacity: 0` on any element or `group` draws nothing — no fill, stroke, shadow, glow, label, or children). When `0 < now.el.opacity < 1` on a kind whose `draw` function does not already apply `el.opacity` (i.e. all kinds except `icon`, `image`, `text`, and `line`, which already apply `el.opacity` to their stroke/picture/text while keeping `icon.tile` and `image.border`/`shadow` at their own opacities for R5 golden compatibility), `drawElements` scales `now.transform.alpha *= now.el.opacity` before calling `draw` (and in `drawGroup` when staggered, `own.alpha *= el.opacity`), so `withTransform`'s `ctx.globalAlpha *= st.alpha` attenuates the entire element and all group children multiplicatively without altering a single canvas call when `opacity === 1` (R5).

## Sequencing

- D1 (`origin` in model, `AnimState`, `animate`, `withTransform`, `applyTransform`) → D2 (compact `origin` schema and `resolveOrigin` in `expandScene`) → D3 (`elementOpacity` field across all component descriptors + schema updates) → D4 (effective opacity multiplication and `<= 0` short-circuit in `drawElements`, `drawGroup`, and `placedElementsAt`) → unit and integration tests.

## Trade-offs

- Keeping `origin` as an optional element property (`origin?: { x: number; y: number }`) carried on `AnimState` (`originX`, `originY`) vs adding mandatory `originX`/`originY` fields to every default element (D1). Pros: existing scenes, preset recipes (`built-in.fixture.json`), and `recipeFromElement` diffs stay 100% unchanged when `origin` is not set (R5); `withTransform` and `applyTransform` receive the pivot directly from `st: AnimState` without changing the signature of any of the 23 component `draw` functions (Principles 1, 2 — KISS & SRP). Cons: `origin` is validated in `ElementSchema` and `CompactElementSchema` alongside `tracks` and `effects` rather than as a descriptor number field. Mitigation: `OriginSchema` is defined once and shared by `element-schema.ts` and `compact.ts` (Principle 3 — DRY).
- Descriptor-level `opacity` field with `.default(1)` on all 23 component kinds vs an optional non-descriptor field (D3). Pros: R3 explicitly requires `opacity` to be exposed in the schema, compact format, keyframe tracks (`animatable`), and inspector for every registered component kind; declaring it in the descriptors gives schema, compact, `keyframe_set` (`d.animatable`), and inspector controls automatically via A23 with zero special cases in tracks or inspector (Principles 1, 3). Cons: `built-in.fixture.json` in `src/presets/recipes.test.ts` and `src/test/legacy-schema.ts` record pre-053 shapes for `rect`, `ellipse`, `group`, and `particles` without `opacity`. Mitigation: `.default(1)` on the Zod schema lets all pre-053 JSON scenes parse seamlessly, and `recipes.test.ts` / `legacy-schema.ts` account for the `opacity: 1` default just as they already do for `anim` (013), `stagger` (018), `frame` (017), and `route` (021).
- Short-circuiting `effectiveOpacity <= 0` and folding `el.opacity` into `transform.alpha` in `drawElements` vs rewriting all 23 component `draw` functions (D4). Pros: one centralized check in `drawElements` guarantees that any element or `group` with effective opacity `0` draws nothing at all (including `line`, `icon.tile`, `image.border`, `rect` fill/stroke/label, and `group` children, satisfying R4), and when `opacity === 1` (the default), `transform.alpha` and the `RecordingCtx` call log are 100% identical to before 053 so all golden render hashes pass untouched (R5). Cons: the 4 kinds that already read `el.opacity` internally (`icon`, `image`, `text`, `line`) must not have `el.opacity` multiplied a second time when `0 < el.opacity < 1`. Mitigation: a small constant set `OWN_OPACITY_KINDS` in `render.ts` skips multiplying `transform.alpha` by `el.opacity` for those 4 kinds when `el.opacity > 0`, while still short-circuiting all of them when effective opacity is `<= 0`.
